## 1. Purpose

Gate every Pokémon evolution behind two conditions, both required:

1. The normal evolution condition (level, item, trade, friendship, etc.) is satisfied, **and**
2. The trainer's badge count has unlocked the competitive tier of the **resulting** (target) species.

This plan covers the engine changes, data changes, special cases, and tests. It does **not** cover encounter-table edits or evolution-item placement in maps/shops (those belong to the encounters workstream).

## 2. Tier ↔ Badge Mapping (decision required)

The design doc labels stages by gym number but never states whether a tier unlocks *entering* or *clearing* that gym. The level-cap semantics already in the engine (`src/caps.c:25-31`: cap = the value at the **first unset** badge flag) settle this:

| Stage | Tier | Badges held during stage | Level cap |
|---|---|---:|---:|
| Gym 1 | LC | 0 | 13 |
| Gym 2 | PU | 1 | 20 |
| Gym 3 | NU | 2 | 30 |
| Gym 4 | RU | 3 | 36 |
| Gym 5 | UU | 4 | 42 |
| Gym 6 | UUBL | 5 | 50 |
| Gym 7 | OU | 6 | 55 |
| Gym 8 | OU | 7 | 60 |
| Post-game | — | 8 | 100 |

Evidence this is the intended reading: the doc lowers Dratini → Dragonair to level 20 "because PU has a cap of 20". That only makes sense if PU is *played at* cap 20 — i.e. during the Gym 2 segment, when the player holds 1 badge. If PU unlocked at 2 badges, the cap would already be 30 and lowering to 20 would be pointless.

**Proposed unlock table:**

```c
EVO_TIER_LC   -> 0 badges
EVO_TIER_PU   -> 1 badge
EVO_TIER_NU   -> 2 badges
EVO_TIER_RU   -> 3 badges
EVO_TIER_UU   -> 4 badges
EVO_TIER_UUBL -> 5 badges
EVO_TIER_OU   -> 6 badges
```

> **Designer check:** confirm this "tier is legal during its gym's segment" reading. If tiers should instead unlock as the *reward* for beating that gym, add +1 to every threshold. All code below reads from one table, so the change is one line per tier.

Gameplay consequence worth noting: with 0 badges nothing can evolve at all (even Caterpie → Metapod), because no LC→LC evolutions exist in the roster. This matches the doc ("Low-level evolutions that would normally occur during LC remain blocked if their evolved form is not legal yet").

## 3. Architecture Overview

All evolution paths in the engine funnel through one function:

`GetEvolutionTargetSpecies()` — `src/pokemon.c:4436-4631`

Its per-mode loops (`EVO_MODE_NORMAL`, `TRADE`, `ITEM_USE`, `ITEM_CHECK`, `BATTLE_SPECIAL`, `OVERWORLD_SPECIAL`, `SCRIPT_TRIGGER`, `BATTLE_ONLY`) all converge on a single tail at `src/pokemon.c:4619-4631`:

```c
    // Pikachu, Meowth, Eevee and Duraludon cannot evolve if they have the
    // Gigantamax Factor. ...
    if (GetMonData(mon, MON_DATA_GIGANTAMAX_FACTOR)
     && GetGMaxTargetSpecies(species) != species
     && GetGMaxTargetSpecies(targetSpecies) == targetSpecies)
    {
        return SPECIES_NONE;
    }

    return targetSpecies;   // <-- gate goes here
}
```

One check before that final `return` gates **every** evolution mode at once. Blocked evolutions never start the evolution scene; callers fall back to their existing `SPECIES_NONE` behavior (`gText_WontHaveEffect`, `EVO_EVENT_IMPOSSIBLE`, or no-op after battle), so no scene changes are needed for the core feature.

## 6. Step 3 — `GetPlayerBadgeCount()` helper

No shared badge-count helper exists; the loop is duplicated in `src/match_call.c:1833`, `src/battle_script_commands.c:9909`, `src/shop_criteria.c:49`, and `src/main_menu.c:2207`. Add one canonical helper:

`src/event_data.c` (it already owns `gBadgeFlags[]`, line 39-48):

```c
u8 GetPlayerBadgeCount(void)
{
    u8 count = 0;
    for (u32 i = 0; i < NUM_BADGES; i++)
    {
        if (FlagGet(gBadgeFlags[i]))
            count++;
    }
    return count;
}
```

`include/event_data.h`: add the prototype next to `FlagGet` (line 30).

Notes:

- This counts set flags, not "badges in order", so it stays correct even if a player ever earns badges out of order (the map design has a fixed gym order, but the helper should not depend on it). `GetNumOwnedBadges()` in `match_call.c` stops at the first unset flag and cannot be reused.
- Optional cleanup (separate commit): route the four duplicated loops through this helper.

## 7. Step 4 — Per-species tier data

New file `src/data/pokemon/evolution_tier_gates.h`:

```c
// Plastic Ox: competitive tier per species, used to gate evolutions.
// Species not listed default to EVO_TIER_NONE (never gated).
// Keyed by species id after SanitizeSpeciesId(); base forms cover their
// regional/alt forms unless a form is listed explicitly.
static const u8 sSpeciesEvolutionTier[NUM_SPECIES] =
{
    // PU (unlock: 1 badge)
    [SPECIES_IVYSAUR]    = EVO_TIER_PU,
    [SPECIES_CHARMELEON] = EVO_TIER_PU,
    ...
    // NU (unlock: 2 badges)
    [SPECIES_PIDGEOT]    = EVO_TIER_NU,
    ...
    // OU (unlock: 6 badges)
    [SPECIES_GYARADOS]   = EVO_TIER_OU,
    [SPECIES_MILOTIC]    = EVO_TIER_OU,
    [SPECIES_DUGTRIO]    = EVO_TIER_OU,
    [SPECIES_BRELOOM]    = EVO_TIER_OU,
    ...
};
```

Decisions:

- **Lookup table, not a `SpeciesInfo` field.** Adding `.tier` to `struct SpeciesInfo` (include/pokemon.h:391-520) is structurally feasible (spare bits exist at `padding4:8`, line 490), but species data is hand-written across 9 `gen_*_families.h` files with no code generator, so a field means touching every entry. A single designated-initializer table is one file, one diff, one review. Only ~370 Gen 1-3 species need values; everything else defaults to `EVO_TIER_NONE`.
- Only **evolution targets** are functionally read, but list every released species per tier anyway — the table doubles as machine-checkable documentation of the design doc's tier lists, and a CI/script cross-check (Step 10) can diff it against `plasticox_encounters_v1.md`.
- The four **OU-only families** (Magikarp → Gyarados, Feebas → Milotic, Diglett → Dugtrio, Shroomish → Breloom) need no special code: Gyarados/Milotic/Dugtrio/Breloom simply carry `EVO_TIER_OU`. Encounter availability is a separate (map/wild-data) concern.
- The 12 **Ubers** (Mewtwo, Mew, Wynaut, Wobbuffet, Lugia, Ho-Oh, Latias, Latios, Kyogre, Groudon, Rayquaza, Deoxys) stay unmapped — none of them evolve, so the gate never fires.
- **Feebas → Milotic**: keep the Beauty evolution (`IF_MIN_BEAUTY` condition, unchanged); Milotic's `EVO_TIER_OU` entry does the gating. If the design later switches to Prism Scale, it becomes an `EVO_ITEM` entry — still gated by the same table.

Accessor in `src/pokemon.c` next to `GetSpeciesEvolutions` (line 3326):

```c
static enum EvolutionTier GetSpeciesEvolutionTier(enum Species species)
{
    return sSpeciesEvolutionTier[SanitizeSpeciesId(species)];
}
```

## 8. Step 5 — The central gate

`src/pokemon.c`, at the tail of `GetEvolutionTargetSpecies` (line 4619-4631), after the Gigantamax check:

```c
bool32 IsEvolutionTierUnlocked(enum Species targetSpecies)
{
    if (!P_EVOLUTION_TIER_GATING)
        return TRUE;
    return GetPlayerBadgeCount() >= sEvolutionTierBadgeRequirement[GetSpeciesEvolutionTier(targetSpecies)];
}
```

```c
    // Plastic Ox: block the evolution if the target species' tier is not yet
    // unlocked by the player's badge count. Placed at the single convergence
    // point so every evolution mode (level, item, trade, battle, overworld,
    // script) is gated uniformly. canStopEvo is deliberately left untouched:
    // a tier-blocked evolution never starts, it is not "stopped".
    if (targetSpecies != SPECIES_NONE && !IsEvolutionTierUnlocked(targetSpecies))
        return SPECIES_NONE;

    return targetSpecies;
```

Why the tail and not the per-mode loops:

- One edit covers all 8 modes, including future callers.
- The probe/commit pair (`CHECK_EVO` then `DO_EVO`) is always called back-to-back by every caller, so gating identically in both states is correct and has no side-effect risk (item/bag removal happens inside `DoesMonMeetAdditionalConditions` in the `DO_EVO` branch, which is never reached when the probe returns `SPECIES_NONE`).

Mode-specific behavior to be aware of:

- **`EVO_MODE_ITEM_CHECK`** (party-menu "can this stone be used?" probe, `src/party_menu.c:1183`): gating it makes an early-obtained stone show "It won't have any effect" until the tier unlocks. This is the desired behavior — it implements the doc's **Item Safety Rule** ("Evolution items do not override tier legality; Water Stone may exist in RU for Poliwrath, Vaporeon remains blocked until UUBL") with zero extra code, and the UX is honest about why.
- **`EVO_MODE_TRADE`** (in-game trades, `src/trade.c:3875` etc.): a trade evolution whose target tier is locked simply does not trigger on receipt. Map design should avoid offering such trades early, or accept the unevolved result.
- **`EVO_MODE_BATTLE_ONLY`** (Tandemaus-style) and **`EVO_MODE_SCRIPT_TRIGGER`**: not used by the Gen 1-3 roster; gated uniformly anyway, so future data stays safe by default.

Unchanged by design: Everstone/`HOLD_EFFECT_PREVENT_EVOLVE` handling, the Kadabra Everstone quirk, the Gigantamax-factor block, and evolution ordering ("first matching entry wins").

## 9. Step 6 — Shedinja and the Nincada special case

Shedinja is **not** produced by `GetEvolutionTargetSpecies` — no mode handles `EVO_SPLIT_FROM_EVO`. It is generated as a side effect of the Ninjask evolution scene by `CreateShedinja()` (`src/evolution_scene.c:551-599`, called at `:839-840`). The Plastic Ox split-legality design needs two changes.

### 9a. Gate the split itself

Inside `CreateShedinja`'s split branch (`src/evolution_scene.c:557-563`), add the tier check so a locked Shedinja never appears as a free side effect:

```c
        if (evolutions[i].method == EVO_SPLIT_FROM_EVO
         && evolutions[i].param == postEvoSpecies
         && gPartiesCount[B_TRAINER_PLAYER] < PARTY_SIZE
         && IsEvolutionTierUnlocked(evolutions[i].targetSpecies)   // NEW
         && DoesMonMeetAdditionalConditions(mon, evolutions[i].params, NULL, PARTY_SIZE, NULL, CHECK_EVO))
```

### 9b. Generate Shedinja when the main evolution is tier-blocked

Design doc rule: Nincada (LC) → Ninjask (UU) + Shedinja (PU). At PU (1 badge), a level-20+ Nincada that levels up with a free party slot and a Poké Ball must produce Shedinja **while staying Nincada**. At UU (4 badges), normal evolution into Ninjask resumes (and still produces Shedinja via 9a).

New helper in `src/evolution_scene.c` (declared in `include/evolution_scene.h`):

```c
// Plastic Ox: if the mon's level-based evolution is blocked ONLY by the tier
// gate, but it has an EVO_SPLIT_FROM_EVO sibling whose tier IS unlocked,
// generate the split species without evolving. (The Nincada/Shedinja rule.)
bool32 TryGenerateTierBlockedSplitEvolution(struct Pokemon *mon)
{
    if (!P_EVOLUTION_TIER_GATING)
        return FALSE;

    enum Species species = GetMonData(mon, MON_DATA_SPECIES, 0);
    u32 level = GetMonData(mon, MON_DATA_LEVEL, 0);
    const struct Evolution *evolutions = GetSpeciesEvolutions(species);
    if (evolutions == NULL)
        return FALSE;

    // 1. Find the level-based main evolution that fired but is tier-blocked.
    for (u32 i = 0; evolutions[i].method != EVOLUTIONS_END; i++)
    {
        if (evolutions[i].method != EVO_LEVEL || evolutions[i].param > level)
            continue;
        if (IsEvolutionTierUnlocked(evolutions[i].targetSpecies))
            continue;  // main evolution is legal; normal path handles it
        if (!DoesMonMeetAdditionalConditions(mon, evolutions[i].params, NULL, PARTY_SIZE, NULL, CHECK_EVO))
            continue;

        // 2. Main evolution is tier-blocked. Try its split siblings.
        for (u32 j = 0; evolutions[j].method != EVOLUTIONS_END; j++)
        {
            if (evolutions[j].method == EVO_SPLIT_FROM_EVO
             && evolutions[j].param == evolutions[i].targetSpecies
             && IsEvolutionTierUnlocked(evolutions[j].targetSpecies))
            {
                CreateShedinja(species, evolutions[i].targetSpecies, mon);
                return TRUE;   // see note on party-slot/message below
            }
        }
    }
    return FALSE;
}
```

Implementation notes:

- `CreateShedinja` is currently `static`; keep it static and put the helper in the same file. It already re-checks the party-slot and `IF_BAG_ITEM_COUNT` conditions, consumes the ball, and sets the Pokédex flags.
- Return value is for messaging/testing; `CreateShedinja` silently does nothing when the party is full or no ball is in the bag, which matches vanilla Shedinja behavior (no error text).

Call sites — the two level-up paths, each right after a `SPECIES_NONE` result from the `EVO_MODE_NORMAL` probe:

1. `src/party_menu.c` — `ItemUseCB_RareCandy` / `PartyMenuTryEvolution` fallback branches (around `:5847-5862` and `:6037-6041`): when the probe returns `SPECIES_NONE`, call `TryGenerateTierBlockedSplitEvolution(mon)` before showing `gText_WontHaveEffect`. If it returns TRUE, show a short message instead (new text, e.g. `gText_PkmnShedShell` — "A shed shell joined the party!"), skipping the "won't have effect" text. The Rare Candy's level-up already happened; only evolution was suppressed.
2. `src/battle_main.c` — `TryEvolvePokemon()` (`:5617-5657`): after the loop finds no evolvable party member... actually per-mon: when `species == SPECIES_NONE` for mon `i` after the `EVO_MODE_BATTLE_ONLY` check, call the helper once per mon. No scene is shown; optionally emit a battle message line.

Keep the helper generic (any species with a tier-blocked main evo + unlocked split sibling gets the behavior), but note that Nincada is the only such family in the roster.

## 12. Step 9 — UX (optional phase 2)

Core gating is silent: a tier-blocked Pokémon just does not evolve. That is correct but opaque. Recommended polish, in priority order:

1. **HGSS Pokédex evolution screen** (`src/pokedex_plus_hgss.c`, `PrintEvolutionTargetSpeciesAndMethod` at `:6429`, method switch at `:6515-6555`): append ", needs N badges" to the method string when `GetSpeciesEvolutionTier(target)` is above the player's current unlock. Cheap, high value, uses existing UI.
2. **Blocked-evolution message** for stone use: distinguish "no effect ever" from "not yet" in the party-menu fallback (`src/party_menu.c:5862` / `item_use.c:1371`). Requires a small query helper (e.g. `GetEvolutionTargetSpeciesIgnoringTier(...) != SPECIES_NONE`) to know the block came from the gate, then a new text like `gText_CantEvolveYet` ("It seems it can't evolve yet…"). Defer unless playtesters find the silence confusing.
3. **Level-up blocked notice**: a one-line message when a level-up evolution is tier-blocked. Most intrusive to implement (battle text path in `TryEvolvePokemon`); only do this if 1+2 prove insufficient.

## 14. Edge cases and non-goals

- **Forms:** the table is indexed by `SanitizeSpeciesId`, which maps to the real species id; regional forms are separate species ids. The Gen 1-3 roster has no form-evolution targets to gate; if forms are added later they need their own table rows.
- **In-game NPC trades:** gated like everything else (Step 8 note). Map design should not hand out Kadabra trades before UUBL.
- **Link trades:** gated by the receiving save's badges. Acceptable for a single-player hack.
- **Everstone / cancel-with-B:** unchanged; both still suppress otherwise-legal evolutions.
- **Gigantamax factor:** unchanged; evaluated before the gate.
- **Daycare, Rare Candy, battle EXP:** untouched by the gate; level caps are Step 8, not this feature.
- **Evolution item release schedule** (Moon Stone at PU, etc.) and **encounter tables**: out of scope — encounters workstream. The gate makes the Item Safety Rule automatic regardless of when items are distributed.
- **Ordering inside an evolution list:** the gate runs on the chosen target, so a locked higher-priority entry makes the whole probe return `SPECIES_NONE`; the loop's "first match wins" never falls through to a lower-priority legal sibling. No current family mixes gated/ungated targets for the same method+param, so this is theoretical; note it if future data adds such families.

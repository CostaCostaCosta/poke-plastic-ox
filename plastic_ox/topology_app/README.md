# Plastic Ox Topology Builder

A manual drag-and-drop Gradio editor for assembling the Plastic Ox overworld from existing Gen I–III map modules.

## What it does

- Large central topology canvas (resizable vertically) with a 2600×1800 workspace.
- Drag required towns, story-linked routes, required dungeons/landmarks, any unused numbered Gen I–III route, and a reusable dungeon/landmark inventory onto the canvas.
- Preserves each source map's cardinal port geometry. Cardinal-to-cardinal connections require opposite-facing ports; cave/warp/transit links may ignore orientation because they are warps rather than seamless map boundaries.
- Shows route categories by orientation and number of connections: vertical, horizontal, elbow, T-junction, and four-way.
- Shows actual map PNG previews whenever `assets/images/<asset>.png` exists. Missing assets automatically fall back to an abstract topology preview.
- Each source map is unique by default, so you cannot accidentally place the same route twice.
- Choose a gate (`Surf`, `Cut`, `Badge`, `Story flag`, `Late-game`, etc.) before connecting ports. Gated edges are dashed.
- Validation reports required-part coverage, unused exterior town ports, isolated pieces, early/open cycle rank, physical/endgame cycle rank, and a bounding-box footprint proxy.
- Export/import the topology as JSON. Export a schematic SVG for review.

## Run

```bash
cd plastic_ox_topology_app
python -m pip install -r requirements.txt
python app.py
```

Gradio will open the editor in your browser.

## Current asset coverage

The `assets/images/` folder is populated from `imagesv0.4.zip`. That archive predates story v0.6.1, so several required maps are deliberately represented by abstract previews until their PNGs are added. Important missing v0.6.1 assets include Pallet Town, Mt. Moon, Blackthorn, Ice Path, Burned Tower, Pokémon Tower, Pokémon Mansion, and Silph Co.

To add/replace an image, put its PNG in `assets/images/` using the filename in `parts_catalog.json` and restart the app. For example:

- `PAL.png`
- `MTMOON.png`
- `BLACK.png`
- `ICEPATH.png`
- `BURNED.png`
- `PKTOWER.png`
- `MANSION.png`
- `SILPH.png`

Numbered routes use `R<number>.png` (for example `R44.png`).

## Catalog structure

`parts_catalog.json` is generated by `build_catalog.py` and is intended to be edited/refined as the map-port inventory improves. `build_catalog.py` contains:

- the full 80-route Kanto/Johto/Hoenn inventory used by the project,
- v0.6.1 required towns,
- required story areas,
- story-linked route anchors,
- a reusable Gen I–III dungeon/landmark inventory.

Run `python build_catalog.py` after editing the source metadata.

## Design behavior

The editor intentionally distinguishes **physical topology** from **progression topology**. Build all physical links you want available in the endgame, then gate edges with HMs, badges, or story flags. The metrics make it easy to target a mostly linear early game with a more meshed endgame while minimizing unused town exits and the region's overall footprint.
